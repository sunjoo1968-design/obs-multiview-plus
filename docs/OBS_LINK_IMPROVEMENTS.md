# Sunjoo OBS Link Multiview 0.5.4

제작자 SunjooAn · Windows x64 / OBS 32.2.2

이번 조합: Controller 0.1.2, Multiview 0.5.4, Tally 1.6.0-obs.6. 기존 DLL/source/vendor ID와 카메라 배정은 유지한다. 세 네이티브 모듈은 연동 규격 2를 보고하며 Tally 허브의 OBS 설정에서 실제 연결·설치 버전·전체 호환 여부를 표시한다. 옵션 OFF도 실제 OBS 연결 상태를 표시하지만 네이티브 설치 정보 수집은 중지한다. 이전 bridge가 버전을 보고하지 않는 것과 미설치 상태를 구분한다. 설정을 나중에 열거나 재접속해도 상태를 재전달한다.

MIX 도중 TAKE는 A/B 카메라와 배치를 복제하고 혼합 비율에서 남은 전환을 PGM 내부에서 독립 진행한다. 카메라 영상은 계속 갱신되며 정지 이미지 방식이 아니다. clone-of-clone와 완료 후 재복제도 지원한다. 멀티뷰·탈리는 실제 기여 중 양쪽 카메라를 표시하고 완료 후 이전 카메라를 해제한다. CUT·일반 장면·기존 source 매핑도 유지한다. Source Switcher의 표준 Fade와 ME2의 표준 Fade를 지원한다. 임의의 외부 전환 효과 진행 상태 복제는 이 구현의 범위가 아니다.

설치는 방송이 없는 시간에 사용자가 OBS/허브를 종료한 뒤 기존 DLL 파일명 그대로 교체한다. 같은 모듈을 이름만 다르게 추가하지 않는다. 리스너 firmware·UDP·vMix·ATEM은 변경하지 않았고 firmware 재설치가 필요하지 않다. 현장 설치본은 자동 변경하지 않았다. Tally 저장소와 릴리스는 비공개로 유지한다.

검증: 실제 OBS ME1·ME2 중간 MIX TAKE의 두 카메라 기여·독립 완료·이전 카메라 OFF 및 정상 종료, native clone-of-clone·완료 후 복제, MIX 복제 100회 할당 16316→16316, idle 복제 500회 13686→13686, Multiview 2000 조회 13914→13914, Tally 2000 조회 8414→8414. 10분 통합 반복 569 TAKE/28 인증 재접속 통과. 최종 결과 수치는 각 검증 보고서에서 확인한다.

이 결과는 격리 환경의 10분 시험이며 실제 장치의 수 시간 방송·네트워크 장애·오디오 품질을 보장하는 시험은 아니다. 개별 모듈의 반복 조회·복제 할당은 시작값으로 돌아왔다. OBS 전체 종료 로그는 환경에 따라 잔여 할당을 보고했다(Multiview 시험 첫 실행 1건/초기화 후 0건, Tally 종료 시험 첫 실행 2건/이후 1건). 따라서 OBS 전체의 누수 0건을 주장하지 않는다.

최종 검증: Hub Jest 28개 suite, 277개 통과·기존 1개 skip; backend/frontend 및 Windows 실행 파일 빌드 통과. 최종 모듈 조합의 ME1/ME2 MIX TAKE·규격 2 확인 재시험 통과. 600초 soak는 마지막 t=0 경계 보완 직전 조합이며 보완 후 통합 재시험을 별도로 통과했다. Controller 재시작 CREATED/RESTORED, Hub 늦은 설정 화면 상태 재전달, Tally polling 5회/idle 1회 정상 종료 및 Multiview 설정/전체화면/재열기 실행 검증 통과.

사용자 확정(2026-10-08): MIX 중 TAKE는 남은 MIX를 독립적으로 끝까지 진행한다. 이전 릴리스, 현장 설치·설정, 사용자 3D 작업과 Multiview 로컬 이력은 보존한다.
